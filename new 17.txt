# PHASE 4 — MY DAY & SCRUM

## Goal

Build the complete employee daily-work experience.

## Employee Sign-In

Employee opens:

`My Day`

They see:

- Date
- Schedule
- Previous unfinished tasks
- Previous scrum
- Backlog
- Obstacles

Employee completes their sign-in scrum.

Example:

Project: NZF  
Task: Homepage Development  
Starting Progress: 25%

Then:

`Sign In`

---

## During the Workday

Employee can:

- Update task progress
- Add tasks
- View backlog
- Start break
- End break
- Start meeting
- End meeting
- Report obstacle

Example:

25%  
↓  
50%  
↓  
75%  
↓  
100%

Progress history is preserved.

---

## Sign-Off

Employee completes final scrum.

Each task gets a final percentage.

### If task = 100%

Task becomes:

`Completed`

### If task < 100%

Task automatically carries to the next workday.

Example:

75% today  
↓  
Tomorrow starting progress = 75%

---

## Sign Back In

If an employee signs off accidentally or returns later:

`Sign Back In`

Previous attendance history is preserved.

# DEVELOPMENT RULES

These rules apply to every phase.

## 1. One Source of Truth

Each business fact has one authoritative database source.

Do not independently save the same value in several tables.

---

## 2. No Duplicate Features

If a component already exists, reuse it.

Examples:

- Tables
- Buttons
- Modals
- Filters
- Status badges
- Cards
- Navigation

---

## 3. No Duplicate Business Logic

Approvals should have one workflow.

Attendance calculations should have one workflow.

Scrum carry-over should have one workflow.

Do not implement different versions on different pages.

---

## 4. Database Security First

Frontend visibility is not security.

Supabase RLS remains responsible for actual data access.

---

## 5. Sensitive Actions Run Through Trusted Server Logic

Examples:

- Request approval
- Request rejection
- Attendance correction
- Leave ledger changes
- Audit creation
- Administrative imports

---

## 6. No Temporary Second Backend

Use the existing production Supabase architecture.

Do not create another temporary database for frontend development.
